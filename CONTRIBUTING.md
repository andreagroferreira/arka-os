# Contributing to ArkaOS

> Thanks for contributing. ArkaOS is governed by the Constitution
> (`config/constitution.yaml`) and a non-negotiable evidence flow: real
> test runs, explicit approvals, and an absolute-veto Quality Gate.
> This file is the practical playbook.

## Before you start

- Work on a **feature branch** off `master` — never commit directly to
  master (branch-isolation, NON-NEGOTIABLE).
- **Conventional commits** only: `feat(scope): ...`, `fix(scope): ...`,
  `docs(scope): ...`, `chore(scope): ...`.
- Every change to docs or code runs through the same gates. Small doc
  fixes may use `[arka:trivial] <reason>` for single-file edits under
  10 lines; anything else runs the 4-gate evidence flow
  (`arka/skills/flow/SKILL.md`).

## The test suite

Run the full suite before and after any change:

```bash
~/.arkaos/bin/arka-py -m pytest tests/python -q -x
```

Expect ~7,900 tests to pass. Never ship with a red suite.

## Generated files — never hand-edit

These are generated by scripts and locked by drift tests. Change the
generator, not the output, then regenerate:

| Generated file | Generator | Drift lock |
|---|---|---|
| `docs/SKILLS-CATALOG.md` | `scripts/skills_catalog_gen.py` | `tests/python/test_skills_catalog_gen.py` |
| `docs/WORKFLOWS-CATALOG.md` | `scripts/workflows_catalog_gen.py` | `tests/python/test_workflows_catalog_gen.py` |
| `knowledge/agents-registry-v2.json` | (see `scripts/tools/`) | `test_marketplace_gen.py` (version bump) |
| Marketplace/plugin JSONs | `scripts/marketplace_gen.py` | `test_marketplace_gen.py` |

The drift tests compare `generate()` byte-for-byte against the committed
file — a hand edit fails CI immediately. Regenerate with:

```bash
~/.arkaos/bin/arka-py scripts/skills_catalog_gen.py
~/.arkaos/bin/arka-py scripts/workflows_catalog_gen.py
```

Also verify against the canonical counters (`scripts/tools/docs_stats.py`):
**341 skills** (326 department + 15 `/arka`), **89 agents**, **17 departments**.

## Documentation conventions

- Counts are **never hand-typed** — run `docs_stats.py` and paste.
- The user wiki lives in `wiki/` (numbered pages, `Home.md` index);
  deep reference lives in `docs/`. New wiki pages need a row in
  `wiki/Home.md` and a link from the previous page.
- Department → hub prefixes differ from directory names
  (`marketing→mkt`, `finance→fin`, `strategy→strat`).
- Check links: no broken `.md` links inside `wiki/` (the `../docs/`
  style is valid; `20-For-Everyone.md`-style forward links are only
  acceptable one page ahead).

## Quality Gate

Every deliverable is reviewed by the Quality Gate department (Marta /
Eduardo / Francisca — absolute veto) before it reaches the operator.
Submit via the `qg_submit` tool or the `/arka qg` flow, and address
every rejection item — a second rejection on the same point is a
constitution violation (`mandatory-qa`).

## Release pipeline

Releases follow the 7-step pipeline in `CLAUDE.md` — preflight
(`core/release/preflight_cli.py`) is step 0 and a FAIL stops the
release. The catalog drift tests are part of that preflight.

## Areas that need care

- **Skills** (`arka/skills/`) — read `docs/SKILL-STANDARD.md` and
  `docs/CREATING-SKILLS.md` first; skills are evaluated before they are
  kept (mandatory-skill-evaluation).
- **Agent YAMLs** (`departments/*/agents/`) — validated by the agent
  schema; DNA consistency is checked on load.
- **Secrets** — never commit keys; `.env` files are referenced as
  `${VAR}` placeholders only.
